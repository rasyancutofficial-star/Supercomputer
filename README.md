# Guardian — 디스코드 보안·관리 봇

요청한 경고·타임아웃·테러 대응·사용자 및 채널 화이트리스트 기능을 담은 Python 봇입니다. 디스코드에 직접 설치된 상태는 아니며, 본인의 봇 토큰을 설정하고 PC 또는 서버에서 실행해야 합니다. 한국어 슬래시 명령어 25개를 제공합니다.

## 먼저 알아둘 기본 동작

| 기능 | 기본값과 동작 |
|---|---|
| 경고 추가·감소 | 1회 1~1,000점, 감소 후 최솟값 0점 |
| 경고 한도 | 기본 5점, 서버별 1~1,000점으로 변경 |
| 한도 도달 처분 | 기본 **서버 차단**. **추방**으로 변경 가능 |
| 타임아웃 | 수치 입력 + 분·시간·일 선택. **최대 20일** |
| 도배 | 같은 계정이 서버 전체에서 5초 내 6개 메시지 |
| 반복 문구 | 15초 내 같은 문구 4회. 대소문자·연속 공백 차이는 무시 |
| 멘션 테러 | 한 메시지의 고유 사용자·역할 멘션 합계 8개 이상 또는 실제 @everyone/@here 멘션 |
| 대량 입장 | 10초 내 서로 다른 10명 입장 → 아래의 입장 보호 작동 |
| 대량 파괴 | 한 실행자의 채널 삭제·역할 삭제·추방·차단이 **20초 내 합계 3회 → 실행자 서버 차단** |
| 위험 링크 | 서버 주인이 등록한 도메인 및 하위 도메인 검사. `scam.example/claim`처럼 스킴 없이 적은 표기도 검사. **초기 목록은 비어 있음** |
| 위험 첨부 파일 | 마지막 확장자가 exe·scr·bat·lnk 등 16개 목록에 있으면 삭제·10분 타임아웃·경고 1점. 서버 주인이 `/차단확장자`로 조정 |
| 같은 문구 교차 게시 | 10분 내 같은 20자 이상 문구를 서로 다른 **3개 채널** 이상에 올리면 감지 |
| 초대 링크 (선택) | **기본 꺼짐.** 켜면 discord.gg 등 초대 링크 삭제·타임아웃·경고 |
| 신규 멤버 제한 (선택) | **기본 꺼짐(0분).** 입장 N분 이내 멤버의 링크·첨부 파일 삭제 |
| 신규 계정 보호 (선택) | **기본 꺼짐(0일).** 기준일보다 어린 계정은 기준 나이가 될 때까지 타임아웃(최대 20일) |
| 관리 변경 경보 | 봇 추가, 위험 권한의 역할 추가·부여, 웹훅 생성, 멤버 일괄 정리를 로그 채널에 기록. 중요 경보는 서버 주인 멘션. **자동 처분은 없음** |
| 백업 | 하루 1회 `data/backups`에 데이터베이스 복사본 7개를 보관 |
| ON/OFF | 기능별 스위치(`/보안설정`), 전체 일시정지·자동 재개(`/보안전체`), 버튼 패널(`/보안패널`). 아래 "ON/OFF 사용법" 참고 |
| 저장 | 서버별 경고·설정·경고 이력 SQLite 저장. 재시작해도 유지 |
| 화이트리스트 | 관리자와 서버 주인이 등록·제거. 등록 대상은 경고·타임아웃 부여·경고 처분·모든 자동 보안 대응에서 제외 |
| 채널 화이트리스트 | 등록 채널과 하위 스레드는 도배·반복·멘션 감지 제외. **차단 링크는 계속 검사·제재** |
| 경고 표시 | 경고 명령 결과는 실행 채널에 공개. 대상과 실행자는 ID 대신 사용자 이름 표시 |
| 경고 후속 DM | 수동으로 경고 1·2·3·4점을 추가하면 실행자에게 1·3·5·15일 타임아웃 확인 DM |
| 전용 서버 | `.env`에 지정한 서버에서만 명령어·자동 보안 작동 |

**추방은 재입장이 가능하고, 서버 차단은 차단 해제 전까지 재입장을 막습니다.** 차단에 이미 서버에서 내보내는 효과가 있으므로 한도 도달 시 선택한 처분 하나를 실행합니다. 이 봇의 차단은 기존 메시지를 일괄 삭제하지 않습니다.

자동 보안 기능은 처음부터 켜져 있습니다. 운영진이 채널을 여러 개 정리하거나 대량 추방을 실행하는 경우도 감지 기준에 해당합니다. 그런 작업 전에는 서버 주인이 `/보안전체 끄기`로 자동 보안을 잠시 멈추면 됩니다(정해 둔 시간이 지나면 자동으로 다시 켜집니다). 서버 주인과 이 봇 자신은 자동 감지에서 제외되며, **일반 관리자와 다른 봇은 자동 면제되지 않습니다.**

## 1. 디스코드에서 봇 만들기

1. [Discord Developer Portal](https://discord.com/developers/applications)에 로그인합니다.
2. **New Application**에서 이름을 정합니다. 예: `Guardian`.
3. 애플리케이션의 **Bot** 화면에서 봇 토큰을 발급합니다. 필요하면 **Reset Token**을 사용합니다.
4. **Privileged Gateway Intents**에서 아래 두 항목을 켭니다.
   - **Server Members Intent**: 멤버 입장 감지와 멤버 정보.
   - **Message Content Intent**: 도배·반복·도메인 검사.
5. **OAuth2 → URL Generator** 또는 **Installation → Guild Install**에서 `bot`, `applications.commands` 범위를 선택합니다. 사용자 설치가 아닌 **서버 설치**를 사용합니다.
6. 다음 봇 권한을 선택하여 초대 링크를 만들고 원하는 서버에 초대합니다.

| 필요한 봇 권한 | 사용 이유 |
|---|---|
| View Channels / 채널 보기 | 채널 및 메시지 접근 |
| Send Messages / 메시지 보내기 | 경고 공개 알림·보안 기록 전송 |
| Send Messages in Threads / 스레드에서 메시지 보내기 | 스레드의 자동 경고 공개 알림 |
| Embed Links / 링크 첨부 | 보안 기록 표시 |
| Read Message History / 메시지 기록 보기 | 수정된 메시지 재검사 |
| Manage Messages / 메시지 관리 | 감지된 메시지 삭제 |
| View Audit Log / 감사 로그 보기 | 대량 삭제·추방·차단 실행자 식별 |
| Moderate Members / 멤버 타임아웃 | 타임아웃 |
| Kick Members / 멤버 추방 | 경고 한도 추방 |
| Ban Members / 멤버 차단 | 경고 한도 차단·대량 파괴 대응 |

전체 **Administrator 권한은 필요하지 않습니다.** 봇은 역할이나 채널을 생성·삭제하지 않습니다.

7. 디스코드 **서버 설정 → 역할**에서 봇 역할을 조치할 대상 역할보다 위로 이동합니다. 일반 관리자 계정에 대한 대량 파괴 대응까지 원한다면 해당 관리자 역할보다 봇 역할이 높아야 합니다.
8. 채널 권한 덮어쓰기에서 봇의 채널 보기·메시지 관리·보내기가 막혀 있지 않은지도 확인합니다. 운영진 로그 채널은 운영진만 열람하도록 설정합니다.

토큰은 봇의 비밀번호입니다. **채팅, 스크린샷, GitHub에 올리지 말고 `.env`에만 넣으세요.** 노출됐다면 Developer Portal에서 재발급합니다. 운영진 계정에는 2단계 인증을 켜는 것이 좋습니다.

## 2. Windows에서 실행하기

1. [Python](https://www.python.org/downloads/) **3.12 이상**을 설치합니다. Python 런처(`py`)도 설치합니다.
2. ZIP을 완전히 압축 해제합니다. 압축 프로그램 안에서 바로 실행하지 마세요.
3. 폴더의 **`start.bat`을 더블클릭**합니다. 처음에는 `.env`가 생성되고 메모장이 열립니다.
4. `.env`에 아래 항목을 입력하고 저장합니다.

```dotenv
DISCORD_TOKEN=여기에_본인_봇_토큰
GUILD_ID=여기에_사용할_서버_ID
DATABASE_PATH=data/guardian.sqlite3
```

디스코드 **사용자 설정 → 고급 → 개발자 모드**를 켜고 서버 아이콘을 우클릭하여 서버 ID를 복사할 수 있습니다. `GUILD_ID`에는 채널 ID가 아닌 **사용할 서버 ID**를 입력합니다. 이 값은 필수이며 해당 서버에서만 작동합니다. 먼저 테스트 서버 ID로 확인한 후 운영 서버 ID로 바꿀 수 있습니다. 기존 `.env`의 `TEST_GUILD_ID`도 호환되며, 둘 다 있으면 `GUILD_ID`가 우선입니다.

5. `start.bat`을 다시 실행합니다. 처음에는 필요한 패키지를 설치하며, 이후에는 `requirements.txt`가 바뀐 경우에만 다시 설치합니다.
6. `연결 완료`가 보이면 디스코드에서 `/도움말`을 입력합니다.
7. 서버 주인 계정으로 `/로그설정 채널:#운영진로그`를 실행하고 `/상태`를 확인합니다.

**실행 창을 닫거나 PC를 끄면 봇도 꺼집니다.** 계속 운영하려면 항상 켜진 PC 또는 Python을 실행할 수 있는 서버가 필요합니다. Android 디스코드 앱 안에서 이 Python 파일을 직접 실행하는 방식은 아닙니다.

## 3. 터미널에서 실행하기

프로젝트 폴더에서 실행합니다. Python 3.12로 로컬 검증했습니다.

### Windows PowerShell

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.venv\Scripts\python.exe bot.py
```

`Copy-Item`은 첫 설정 때만 실행합니다. 이미 설정한 `.env`를 덮어쓰지 마세요.

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp -n .env.example .env
# 텍스트 편집기로 .env의 토큰과 서버 ID를 설정합니다.
.venv/bin/python bot.py
```

한 데이터베이스에는 **봇 프로세스 하나만** 실행합니다. 이 버전은 작은 서버의 단일 프로세스 운영을 기준으로 설계했습니다.

## 4. 명령어 사용법

아래 예시는 슬래시 입력창에서 고르는 값입니다. `대상`, `수치`, `단위` 등의 항목은 디스코드가 자동으로 표시합니다.

| 명령어 예시 | 기능 | 실행 권한 |
|---|---|---|
| `/도움말` | 전체 기능 설명 | 누구나 |
| `/경고조회` | 본인의 경고와 최근 10개 이력 | 누구나 |
| `/경고조회 대상:@멤버` | 다른 멤버의 경고 조회 | 멤버 타임아웃 |
| `/경고추가 대상:@멤버 수치:1 사유:도배` | 경고 추가 | 멤버 타임아웃 + 조건부 처분 권한 |
| `/경고감소 대상:@멤버 수치:2 사유:오인처리` | 경고 감소 | 멤버 타임아웃 |
| `/경고집행 대상:@멤버` | 한도 이상인 멤버의 실패 처분 재시도 | 멤버 타임아웃 + 해당 처분 권한 |
| `/경고한도 수치:7` | 경고 한도를 7로 변경 | 관리자 |
| `/경고처분 방식:추방` | 한도 처분 선택 | 관리자 |
| `/타임아웃 대상:@멤버 수치:30 단위:분 사유:도배` | 30분 타임아웃 | 멤버 타임아웃 |
| `/타임아웃 대상:@멤버 수치:2 단위:일` | 2일 타임아웃 | 멤버 타임아웃 |
| `/타임아웃해제 대상:@멤버` | 타임아웃 해제 | 멤버 타임아웃 |
| `/로그설정 채널:#운영진로그` | 기록 채널 선택 | 서버 주인 |
| `/보안설정 기능:대량입장감지 활성화:False` | 기능별 ON/OFF. 기능: 도배·멘션, 대량 입장, 대량 삭제, 등록 도메인, 위험 첨부 파일, 초대 링크, 관리 변경 경보, 서버 주인 멘션, 같은 문구 교차 게시, 신규 멤버 제한, 신규 계정 보호 | 서버 주인 |
| `/보안전체 상태:끄기 분:60` | 모든 **자동** 보안을 일시정지. 60분 뒤 자동 재개(`분:0`이면 직접 켤 때까지). `상태:켜기`로 즉시 재개 | 서버 주인 |
| `/보안패널` | 버튼으로 전체·기능별 ON/OFF. 🟢 켜짐 · ⚫ 꺼짐. 본인에게만 보이는 패널 | 서버 주인 |
| `/감지기준 항목:20초내위험관리작업수 수치:5` | 위험 작업 기준을 5회로 변경 | 서버 주인 |
| `/감지기준 항목:신규계정보호기준 수치:3` | 가입 3일 미만 계정을 3일이 될 때까지 타임아웃. `0`이면 끔(최대 20) | 서버 주인 |
| `/감지기준 항목:입장직후링크첨부제한 수치:10` | 입장 10분 이내 멤버의 링크·첨부 제한. `0`이면 끔(최대 1,440) | 서버 주인 |
| `/화이트리스트추가 대상:@멤버` | 경고·타임아웃 부여·경고 처분·자동 보안 면제 | 관리자 또는 서버 주인 |
| `/화이트리스트제거 대상:@멤버` | 화이트리스트 제거 | 관리자 또는 서버 주인 |
| `/화이트리스트조회 페이지:1` | 화이트리스트를 20명씩 확인 | 관리자 또는 서버 주인 |
| `/채널화이트리스트추가 채널:#자유채팅` | 도배·반복·멘션 감지 제외, 차단 링크는 검사 | 관리자 또는 서버 주인 |
| `/채널화이트리스트제거 채널:#자유채팅` | 채널 예외 해제 | 관리자 또는 서버 주인 |
| `/채널화이트리스트조회 페이지:1` | 등록 채널을 20개씩 확인 | 관리자 또는 서버 주인 |
| `/보안예외 대상:@신뢰하는봇 예외여부:True` | 화이트리스트 추가·제거의 기존 호환 명령어 | 관리자 또는 서버 주인 |
| `/차단도메인 도메인:example.com 차단여부:True` | 도메인과 하위 도메인 차단 등록 | 서버 주인 |
| `/차단확장자 확장자:docm 차단여부:True` | 삭제할 첨부 파일 확장자 추가·제거 | 서버 주인 |
| `/상태` | 설정·기준·권한·도메인·화이트리스트 ID 확인 | 관리자 |
| `/보안점검` | 서버 보안 설정을 **읽기 전용**으로 점검(2단계 인증·인증 수준·@everyone 권한·관리자 역할·관리자 봇·로그 채널 공개 여부 등) | 관리자 |

`example.com`은 설명용 예시이며 실제 위험 사이트라는 뜻은 아닙니다. 기능·항목은 실제 선택지에서 고르면 됩니다. **경고 추가·감소·조회·집행·한도·처분 명령 결과는 실행한 채널을 볼 수 있는 모두에게 공개됩니다.** 그 외 명령 응답은 실행자에게만 보이고, 운영 기록은 지정한 로그 채널에 남습니다. 채널 접근 권한을 바꾸거나 다른 채널로 공지를 전파하지는 않습니다.

### 화이트리스트의 세부 규칙

- **서버 주인뿐 아니라 `Administrator / 관리자` 권한이 있는 사람도 등록·제거·조회할 수 있습니다.** 역할 이름이 '관리자'인 것만으로는 안 되며 실제 권한을 검사합니다. 멤버 타임아웃 권한만 가진 운영자는 수정할 수 없습니다.
- 서버당 최대 100명입니다. 사용자 ID로 저장하므로 이름을 바꾸거나 재입장해도 유지되고, 서버별 목록은 분리됩니다.
- 등록 대상의 도배·멘션·등록 도메인 메시지를 이 봇이 자동 삭제하지 않습니다. 대량 입장 타임아웃, 대량 파괴 자동 차단도 면제됩니다.
- 자동 경고와 수동 `/경고추가` 모두 막습니다. 과거 경고가 이미 한도 이상이어도 `/경고집행`으로 추방·차단하지 않습니다.
- 등록 대상에 대한 이 봇의 수동·자동 타임아웃 부여도 막습니다. `/경고조회`, `/경고감소`, `/타임아웃해제`는 기존 실행 권한과 역할 순서 조건에 따라 사용할 수 있습니다.
- 등록 전 경고는 지우지 않으며 이미 적용된 타임아웃·차단도 자동 해제하지 않습니다. 면제는 등록 완료 후 적용됩니다. 등록과 조치가 동시에 요청되면 대상별로 순서대로 처리됩니다.
- 화이트리스트에서 제거해도 과거 행동만으로 즉시 처분하지 않습니다. 기존 경고 점수는 유지되므로 이후 경고 추가·집행 시 현재 한도를 적용합니다.
- 기존 버전의 `/보안예외` 목록을 그대로 화이트리스트로 사용합니다. 기존 등록 대상도 이번 버전부터 수동 경고·타임아웃 부여 및 경고 처분이 면제됩니다.
- 등록·제거 기록에는 변경한 관리자 ID와 대상 ID가 남습니다. 이 설정이 디스코드 자체 AutoMod나 다른 봇의 처분까지 해제하지는 않습니다.

### 채널 화이트리스트의 세부 규칙

- 관리자 권한이 있는 사람과 서버 주인이 추가·제거·조회할 수 있습니다. 서버당 직접 등록은 최대 100개입니다.
- 텍스트·공지 채널, 포럼, 스레드, 음성·스테이지 채널의 텍스트 채팅을 선택할 수 있습니다. 상위 채널을 등록하면 그 아래 스레드·포럼 게시물에도 적용됩니다. 카테고리는 등록 대상이 아닙니다.
- 등록 채널에서는 도배·반복 문구·과도한 멘션을 감지하지 않으며 그 메시지는 서버 전체 도배 카운터에도 더하지 않습니다. 일반 채널에서 보낸 메시지는 기존대로 검사합니다.
- **위험 첨부 파일도 예외가 아닙니다.** 초대 링크 차단은 등록 채널에서만 제외되므로 홍보 채널을 등록해 두면 편합니다.
- **차단 링크는 예외가 아닙니다.** `/차단도메인`에 등록된 도메인·하위 도메인이 발견되면 해당 메시지를 삭제하고 기존 규칙대로 10분 타임아웃·경고를 시도합니다. 메시지 수정으로 추가한 링크도 검사합니다. 경고 추가는 기존의 멤버당 60초 간격을 적용합니다.
- 도메인 검사는 해당 보안 기능이 켜져 있고 등록된 도메인이 있을 때 동작합니다. 등록하지 않은 위험 링크를 자동으로 판별하는 기능은 아닙니다.
- **사용자 화이트리스트는 기존 규칙을 유지합니다.** 사용자 자체가 화이트리스트에 있으면 차단 링크를 포함한 자동 보안 대응이 면제됩니다.
- 채널을 등록해도 수동 경고·타임아웃 명령, 대량 입장 보호, 채널·역할 대량 삭제 대응은 그대로 작동합니다. 기존 경고나 이미 실행 중인 처분을 취소하지 않습니다.
- 스레드의 직접 등록을 제거해도 상위 채널이 등록되어 있으면 면제가 유지됩니다. 상위 채널에서 면제를 해제하려면 그 채널의 등록을 제거하세요.
- 목록은 재시작 후에도 유지됩니다. 기존 버전에서 업데이트하면 빈 채널 목록으로 시작하며 기존 사용자 화이트리스트·경고·설정은 보존합니다.

### 이전 버전에서 업데이트하기

봇을 종료하고 새 ZIP의 `bot.py`, `core.py`, **`checkup.py`**, `requirements.txt`, `start.bat`, 안내 파일을 기존 폴더에 덮어쓴 뒤 다시 실행하세요. **기존 `.env`와 `data` 폴더는 유지**합니다. 재시작 시 새 슬래시 명령어가 등록됩니다. 기존 경고·설정은 그대로 이어집니다.

**업데이트하면 바로 달라지는 점:** 위험 첨부 파일 차단과 관리 변경 경보는 **기본으로 켜집니다**(`/보안설정`으로 끌 수 있음). 스킴 없이 적은 등록 도메인도 이제 검사하며, 같은 문구를 여러 채널에 올리는 행동도 감지합니다. 초대 링크 차단, 신규 멤버 제한, 신규 계정 보호는 꺼진 상태로 시작합니다.

### 경고의 세부 규칙

- 서버별 경고와 한도는 분리됩니다. 서버 A의 경고가 서버 B에 적용되지 않습니다.
- 경고를 더한 결과가 한도 **이상**이면 처분합니다. 4점에서 2점을 더해 6점이 되어도 처분합니다.
- 한도 도달 시 명령 실행자에게도 선택된 처분 권한(`Kick Members` 또는 `Ban Members`)이 있어야 합니다. 권한이 없으면 그 경고 추가 요청 자체를 거부합니다. 경고 명령어를 통한 권한 우회를 막기 위한 규칙입니다.
- 본인, 서버 주인, 봇 자신, 실행자와 같거나 높은 역할에는 수동 조치할 수 없습니다. 서버 주인이라도 봇의 역할 순서 제약은 적용됩니다.
- 봇의 처분 요청이 실패해도 **추가된 경고는 유지**하고 실패를 기록합니다. 권한 수정 후 `/경고집행`으로 재시도합니다.
- 경고 한도를 낮춰도 기존 멤버를 즉시 일괄 처분하지 않습니다. 다음 경고 추가 또는 `/경고집행` 시 적용합니다.
- 경고는 추방·재입장 후에도 유지됩니다. 재입장 자체만으로 과거 경고 처분을 재실행하지는 않습니다.
- 경고 감소는 이미 적용한 타임아웃·추방·차단을 자동 해제하지 않습니다. 차단 해제는 서버 설정에서 관리합니다.
- 처분 직후 프로세스가 비정상 종료되면 기록이 `처분 대기`로 남을 수 있습니다. 실제 멤버 상태와 감사 로그를 확인한 뒤 조치하세요. 재시작 시 불명확한 처분을 자동 재실행하지 않습니다.

### 경고 완료 문구와 타임아웃 확인 DM

`/경고추가`가 성공하면 먼저 실행한 채널에 아래 형식으로 공개합니다.

```text
{username}에게 {warn}만큼 경고를 넣었습니다.
```

경고 상세·조회 결과·후속 DM·경고 로그의 대상과 실행자 표시는 사용자 이름을 사용하며 사용자 ID 필드를 표시하지 않습니다. 정확한 사용자 구분을 위한 내부 DB의 ID는 유지합니다. 기록 번호(`#1` 등)는 사용자 ID가 아니라 경고 이력 번호입니다. 사유에 직접 입력한 내용은 공개 결과에도 표시됩니다.

자동 감지로 경고를 추가한 경우도 감지된 채널에 공개 알림을 보냅니다. 봇의 메시지 전송 권한이 없어 알림을 보내지 못해도 저장된 경고와 처분은 유지하고 콘솔에 전송 실패를 기록합니다. 이미 전송된 이전 버전의 메시지는 수정하지 않습니다.

`username`은 대상의 Discord 사용자명, `warn`은 **이번에 추가한 경고 수치**입니다. 누적 경고는 아래의 상세 결과에 별도로 표시합니다. 자동 감지에 의한 경고는 이 DM 과정을 실행하지 않습니다.

완료 문구를 표시한 다음 **경고를 추가한 관리자/운영자에게** 다음 DM을 보냅니다. 경고받은 유저에게 승인 여부를 묻지 않습니다.

| 이번 추가 경고 수치 | DM 질문 |
|---|---|
| 1 | 타임아웃 1일을 주시겠습니까? |
| 2 | 타임아웃 3일을 주시겠습니까? |
| 3 | 타임아웃 5일을 주시겠습니까? |
| 4 | 타임아웃 15일을 주시겠습니까? |

- DM에는 서버명·대상 사용자명·이번 경고 수치와 **적용 / 취소** 버튼을 표시합니다. 대상 ID는 표시하지 않습니다.
- **적용**을 눌러야 타임아웃합니다. 기간은 버튼 적용 시점부터 계산합니다. 취소·5분 만료 시 경고만 유지합니다.
- DM은 그 경고를 추가한 사람만 승인할 수 있습니다. 클릭 시 원래 서버에서 실행자의 현재 권한, 역할 순서, 대상의 현재 화이트리스트 여부를 다시 확인합니다.
- 한 버튼은 한 번만 처리합니다. 그사이 경고가 추가·감소되거나 새 처분 기록이 생겼다면 이전 확인 요청은 취소합니다. 기존 타임아웃이 더 길면 그대로 유지합니다.
- 경고 한도에 도달한 경우 기존 추방·차단 규칙을 우선하고 타임아웃 질문을 보내지 않습니다. 한도 처분이 실패한 경우도 `/경고집행`으로 처리합니다. 이번 추가 수치가 1~4 외의 값이면 DM 질문이 없습니다.
- 실행자가 DM을 받을 수 없으면 경고는 정상 저장하고 명령어 응답에 DM 전송 실패를 알립니다. 이 경우 `/타임아웃`을 직접 사용할 수 있습니다.
- 확인 버튼은 봇 재시작 후에는 사용할 수 없습니다. 필요하면 `/타임아웃`으로 처리하며, 질문을 다시 받으려고 같은 경고를 중복 추가하지 마세요.

### 타임아웃의 세부 규칙

- 1분부터 **20일 = 480시간 = 28,800분**까지 가능합니다. 21일·481시간·28,801분은 거부합니다.
- 수동 `/타임아웃`은 기존 종료 시간을 방금 입력한 기간으로 교체합니다. 기존보다 짧게 설정할 수도 있습니다.
- 자동 보안 타임아웃은 이미 적용된 더 긴 타임아웃을 줄이지 않습니다.
- 서버 주인·관리자에게는 디스코드의 타임아웃 제한이 적용됩니다. 이 봇은 봇 계정도 타임아웃 처리에서 제외합니다.

## 5. 자동 보안이 처리하는 범위

### 도배·멘션·등록 도메인

감지된 메시지를 삭제하고 10분 타임아웃 및 경고 1점을 적용합니다. 경고·타임아웃 시도는 멤버당 60초에 한 번으로 제한하지만, 이후 감지 메시지도 계속 삭제를 시도합니다. 앞서 보낸 메시지를 일괄 삭제하지는 않습니다. 타임아웃이 실패해도 경고는 기록되며, 누적 한도 도달 시 설정한 처분을 시도합니다.

다른 봇의 메시지도 검사합니다. 봇 계정에는 타임아웃 대신 삭제·경고를 적용합니다. 웹훅은 감지 메시지 삭제와 기록만 수행하며 웹훅 자체를 삭제하거나 경고를 부여하지 않습니다.

차단 도메인은 `https://`, `http://`, `www.` 링크의 실제 호스트를 검사하고, 디스코드가 링크로 표시하는 **스킴 없는 표기**(`example.com/claim`)도 본문에서 찾습니다. 등록된 `example.com`은 `a.example.com`에도 적용되지만 `notexample.com`, `example.community`, 이메일 주소(`me@example.com`)에는 적용되지 않습니다. 전달(포워드)된 메시지의 본문·첨부 파일과 봇·웹훅 임베드의 설명도 검사합니다. 유니코드로 적은 도메인은 스킴 링크일 때만 검사합니다. 메시지 수정으로 추가된 차단 링크·대량 멘션도 재검사합니다. 수정된 메시지 조회에는 채널 접근과 메시지 기록 보기 권한이 필요합니다.

**등록 목록은 자동 갱신되지 않습니다.** 신종 피싱 판별, 단축 URL 목적지 추적, 첨부 파일 악성코드 검사, QR 코드 판독, 링크 없는 도메인 문구 검사는 제공하지 않습니다.

### 대량 입장

감지 기준에 도달하면 그 10초 동안 입장한 대상 전체와, 이후 2분간 신규 입장하는 대상에게 10분 타임아웃을 시도합니다. 단순히 동시에 입장했다는 이유로 경고를 올리거나 차단하지 않습니다. 타임아웃해제 명령으로 오인 처리를 바로 풀 수 있습니다. 이 기능은 서버 입장 자체를 봉쇄하지는 않습니다.

### 대량 채널 삭제·역할 삭제·추방·차단

감사 로그 이벤트에 포함된 실행자 ID와 작업 시각을 사용합니다. 멤버 퇴장만 보고 누가 추방했는지 추측하지 않습니다. 동일 로그 ID는 중복 계산하지 않으며, 봇 자신의 경고 처분은 대량 파괴로 계산하지 않습니다.

기준에 도달하면 실행자를 서버 차단합니다. **경고 한도의 처분 방식과 별개**인 긴급 대응입니다. 봇 역할이 실행자보다 높고 봇에 차단 권한이 있어야 합니다. 관리자 계정과 다른 봇도 조건을 충족하면 차단 대상입니다.

이미 발생한 삭제를 되돌리거나, 첫 번째 삭제 전에 차단하지는 못합니다. 디스코드 이벤트 전달 지연과 API 속도 제한으로 추가 피해가 발생할 수 있습니다. 채널·역할 생성 도배, 권한 변경, 멤버 일괄 정리(prune), 서버 설정 변경은 이 버전의 대량 파괴 카운터에 포함되지 않습니다.

### ON/OFF 사용법

세 가지 방법 모두 서버 주인만 쓸 수 있고, 같은 설정을 바꿉니다. 이미 적용된 경고·타임아웃·추방·차단은 끄거나 켜도 되돌려지지 않습니다.

- **기능 하나만:** `/보안설정`에서 기능을 고르고 켜기·끄기를 선택합니다.
  - 신규 멤버 제한(기본 10분)과 신규 계정 보호(기본 3일)는 숫자 기준으로 동작합니다. 끄면 기준이 `0`이 되고, 기준이 `0`일 때 켜면 기본값을 씁니다. 이미 기준이 있으면 그 값을 유지합니다. 값을 바꾸려면 `/감지기준`을 쓰세요.
- **전부 잠시 멈추기:** `/보안전체 상태:끄기 분:60`. 서버 정리처럼 정상 작업이 감지 기준에 걸릴 때 씁니다.
  - **멈추는 것:** 메시지 감지(도배·멘션·도메인·초대·파일·교차 게시·신규 멤버 제한), 대량 입장 보호, 신규 계정 보호, 대량 삭제·추방·차단 대응
  - **계속 동작하는 것:** 수동 경고·타임아웃 명령, 관리 변경 경보와 로그 기록, 데이터 백업
  - 끈 시각과 재개 시각은 저장되어 봇을 재시작해도 유지됩니다. 재개 시각이 지나면 그 순간부터 자동 보안이 다시 동작하고, 저장된 상태와 로그는 1분 안에 정리됩니다.
  - `분:0`은 자동으로 켜지지 않으니 반드시 `/보안전체 상태:켜기`로 다시 켜세요. 꺼진 동안은 서버가 자동 보호를 받지 못합니다. `/상태`와 `/보안점검`에 일시정지 중임이 표시되고, 봇 시작 시 콘솔에도 경고가 남습니다.
  - 일시정지는 로그 채널에 기록되고, 서버 주인 멘션이 켜져 있으면 알림이 갑니다.
- **버튼으로:** `/보안패널`. 버튼을 누를 때마다 바로 적용되며, 마지막으로 누른 뒤 5분이 지나면 버튼이 비활성화됩니다(다시 `/보안패널`). 패널의 전체 보호 버튼으로 끄면 60분 뒤 자동 재개됩니다. 누를 때마다 서버 주인 여부를 다시 확인합니다.

### 추가 보안 기능

메시지·입장 감지는 서버 주인과 화이트리스트 등록 대상에게 적용하지 않습니다. 메시지 감지는 기존과 같은 방식(삭제 → 10분 타임아웃 → 경고 1점, 멤버당 60초 간격)으로 처리합니다. 관리 변경 경보만 예외로, 기록이 목적이라 이들의 작업도 남깁니다.

- **위험 첨부 파일.** 마지막 확장자를 기준으로 합니다(`invoice.pdf.exe`도 감지). 기본 목록: exe, scr, com, pif, bat, cmd, msi, lnk, vbs, vbe, wsf, hta, ps1, jar, reg, cpl. 압축 파일(zip 등) 내부는 검사하지 않으며, 파일 내용을 악성코드 검사하지도 않습니다.
- **같은 문구 교차 게시.** 계정 탈취·스캠 봇은 같은 긴 문구를 여러 채널에 천천히 올립니다. 대소문자·공백 차이를 무시하고 20자 이상인 문구만 비교합니다. 기준 채널 수는 `/감지기준`에서 바꿉니다(기본 3).
- **초대 링크 차단(선택).** discord.gg, discord.com/invite, discordapp.com/invite, discord.me, discord.io, discord.link, dsc.gg, invite.gg를 감지합니다. 홍보가 허용된 채널은 채널 화이트리스트로 제외하세요.
- **신규 멤버 제한(선택).** 입장 직후 계정이 링크(스킴 없는 `.com` 등 일반 도메인 표기 포함)나 첨부 파일을 올리면 감지합니다. 글자만 올리는 것은 제한하지 않습니다.
- **신규 계정 보호(선택).** 입장한 계정이 기준 나이보다 어리면 기준 나이가 될 때까지 타임아웃합니다. 경고 점수는 올리지 않으며, 오인 처리는 `/타임아웃해제`로 풀 수 있습니다. 봇·관리자 계정은 디스코드 제한으로 타임아웃할 수 없어 로그에 실패로만 남습니다.
- **관리 변경 경보.** 감사 로그로 다음을 로그 채널에 기록하며 **자동 처분은 하지 않습니다.** 서버 주인과 화이트리스트 대상의 작업도 기록합니다(봇 자신의 작업만 제외).
  - 봇 추가(중요)
  - 역할에 관리자·서버 관리·역할 관리·채널 관리·웹훅 관리·멤버 차단·멤버 추방 권한이 새로 추가됨. 관리자·서버 관리·역할 관리이거나 `@everyone` 역할이면 중요
  - 위 권한을 가진 역할이 멤버에게 부여됨. 관리자·서버 관리·역할 관리이면 중요
  - 웹훅 생성, 멤버 일괄 정리(중요)
  - 로그 채널이 설정되어 있고 `서버 주인 멘션`이 켜져 있으면, **중요** 경보와 대량 입장·대량 파괴 감지에서 서버 주인 한 명만 멘션합니다. 로그 채널이 없으면 콘솔과 DB에만 남습니다.
- **`/보안점검`.** 설정을 바꾸지 않는 읽기 전용 점검입니다. 멤버·역할 정보는 봇이 캐시한 범위 안에서 확인하며, 대형 서버에서는 일부가 빠질 수 있습니다. 서버 설정은 서버 주인·관리자가 디스코드에서 직접 바꿔야 합니다.

### 계정 해킹 방지에 대한 정확한 범위

이 봇은 비밀번호 탈취·기기 악성코드·세션 탈취를 직접 차단하지 못합니다. 서버 안에서 관찰 가능한 도배, 등록된 위험 링크, 비정상적인 대량 관리 작업에 대응하는 보조 장치입니다. 서버 주인 계정, 자동 감지 예외 계정, 이 봇 자체가 탈취되거나 봇보다 높은 역할이 공격하면 보호에 한계가 있습니다. 봇이 꺼진 동안의 공격은 실시간 처리하지 않으며, 재시작 후 과거 감사 로그를 소급 처리하지 않습니다.

## 6. 데이터와 운영

- `data/guardian.sqlite3`에 서버·사용자·운영자 ID, 경고 점수·사유·처분 결과, 설정을 저장합니다.
- 자동 사건 기록은 90일 뒤 정리하며, 경고 변경 이력은 계속 유지합니다.
- 채팅 메시지 원문 전체나 토큰을 데이터베이스에 저장하지 않습니다. 반복 검사용 해시는 메모리에 잠시 보관합니다.
- 경고·설정·입장 보호 종료 시각은 재시작해도 유지됩니다. 짧은 도배·대량 작업 카운터와 60초 재처리 간격은 재시작하면 초기화됩니다.
- **자동 백업:** 실행 중 하루 1회(마지막 백업이 24시간 이내면 건너뜀) `data/backups/guardian-날짜-시간.sqlite3`를 만들고 최신 7개만 보관합니다. 시작 후 1분 안에 첫 백업이 만들어질 수 있습니다. 같은 컴퓨터가 고장 나면 함께 사라지므로 중요한 서버는 이 폴더를 다른 곳에도 복사하세요.
- **복원:** 봇을 종료하고 `data/guardian.sqlite3`(및 `-wal`, `-shm` 파일)를 치운 뒤 백업 파일을 `guardian.sqlite3`라는 이름으로 복사합니다. DB를 지우면 경고와 설정도 사라집니다.
- 수동 백업은 봇을 정상 종료한 뒤 `data` 폴더 전체를 복사합니다.
- `GUILD_ID`(또는 이전 설정의 `TEST_GUILD_ID`)로 지정한 서버에만 명령어를 등록합니다. 다른 서버의 명령 요청과 보안 이벤트는 처리하지 않습니다. 서버 ID를 비우면 실행을 중단합니다. 이전 버전의 전역 명령어가 남아 보여도 다른 서버에서는 실행을 거부합니다. 다른 애플리케이션의 명령어는 삭제하지 않습니다.
- 이 애플리케이션의 슬래시 명령어는 시작 시 코드와 동기화됩니다. 기존 다른 기능이 있는 봇 토큰 대신 새 애플리케이션의 토큰을 사용하세요.

ON/OFF 테스트 범위: 일시정지 중 모든 자동 처리 중단과 수동 명령·경보 유지, 자동 재개와 정리 기록, `분:0` 무기한 정지, 설정 검증, 숫자 기능의 켜기·끄기 값 규칙, 패널 버튼의 상태 표시·즉시 반영·서버 주인 확인·시간 초과 비활성화. 테스트를 일부러 망가뜨려 결함을 실제로 잡는지도 19건 확인했습니다. **실제 디스코드 접속·권한·감사 로그 이벤트는 여전히 검증하지 못했습니다.** `start.bat`도 윈도우가 아닌 환경이라 실행해 보지 못했습니다.

## 9. 이번 개선에서 고친 문제

| 구분 | 내용 |
|---|---|
| 실행 오류 | 압축 파일에 `.env.example`이 없어 `start.bat`이 첫 실행에서 실패할 수 있던 문제 → 파일을 포함하고, 없어도 `start.bat`이 기본 `.env`를 직접 만듭니다. 패키지는 `requirements.txt`가 바뀐 때만 다시 설치합니다. |
| 오류 | 봇이 재연결 중일 때 `/상태`가 지연 시간(NaN)을 처리하지 못해 실패하던 문제 → `측정 불가`로 표시합니다. |
| 안정성 | 정리 작업이 한 번 실패하면 이후 반복이 조용히 멈출 수 있던 문제 → 오류를 기록하고 계속 동작합니다. 자동 감지 도중 대상이 화이트리스트에 등록되어도 처리기가 예외로 끝나지 않습니다. 인터넷 연결 오류 시 긴 오류 대신 안내 문구로 종료합니다. |
| 보안 | 권한 없는 사용자가 공개 응답 명령을 눌렀을 때 오류 메시지가 채널 전체에 보이던 문제 → 명백한 무권한 호출은 공개 응답 전에 본인에게만 보이게 거절합니다. 최종 권한 판정은 기존처럼 최신 멤버 조회로 합니다. 이후 단계(역할 순서 등)의 오류는 공개 명령에서는 여전히 공개로 보일 수 있습니다. |
| 보안 | 서버 주인 멘션 알림은 디스코드 기본값(everyone·역할 허용)이 아니라 주인 한 명만 허용하도록 제한했습니다. |
| 성능 | 메시지마다 DB에서 설정을 읽던 것을 메모리 캐시로 바꿨습니다. 저장이 성공했을 때만 캐시가 바뀝니다. |
| 정리 | 반복되던 오류 문구·목록 출력·타임아웃 점검 코드를 하나로 합쳤습니다. 기존 동작과 테스트 45개는 그대로 유지합니다. |
| 기능 | 전체 ON/OFF가 없어 서버 정리 때 기능을 하나씩 꺼야 했고, 일부 기능은 숫자 `0`으로만 끌 수 있었습니다. → `/보안전체`, `/보안패널`, 기능별 스위치를 추가했습니다. |
